# 📜 Changelog

Version history for the **Wizstream** extension and this repo, newest first.

Older releases are summarised — full detail for those lives in the git history.


## Recent

| Version | Date | What changed |
|---|---|---|
| **v85** | 2026-07-30 | **bingr-Sirius & mooflix-HDGhar now start like the web: light rung first.** Your report ("streams fine on web, Cloudstream fetches slowly") plus my live measurements told the story: their CDN (the streamraiwind family) serves per-quality ladders — I fetched the real Sirius playlists/segments and they answer fast from anywhere (segment: 200 OK in ~0.1-0.3s regardless of headers), so the CDN was never the bottleneck. The difference was behavior: the web player starts adaptive on a LOW rung and ramps up, while Cloudstream's default pick grabbed the FIRST listed link — the top 8 Mbps 1080p rung — and buffered on it. Both resolvers now collect their per-quality links and emit them LOWEST-quality-first for the Sirius/Bingr servers and Moonflix HDGhar (HV) + the Moonflix mp4 ladder (CH, language order preserved, low-res first inside each language). The default/auto pick now starts light exactly like the web; every rung is still listed with its quality chip, so 1080p is one tap away whenever the network can hold it. Two honest notes: (1) if you *manually* pick the 1080p chip and your ISP can't sustain ~5-8 Mbps to that overseas CDN at that moment, that rung can still buffer — starting low is precisely the fix for that; (2) Sirius sometimes returns nothing for a title (their scrapers are per-title) — that's their catalogue, unchanged. New log lines: `Bingr: emit N link(s) low-first on <server>`, `Moonflix HV: emit N link(s) low-first`, `Moonflix CH: ladder N link(s) low-first`. Carries v84 (sync-line removal, AniList episode titles, franchise cache/hardening) and v83 (no pre-playback verifier). Not pushed to GitHub — your call when to push. |
| **v84** | 2026-07-30 | **Three of your four asks (Sirius/HDghar needs your site details — see chat).** (1) **Sync-status lines removed from descriptions** — the last "👤 AniList: Watching · ep a/b" readout no longer pins itself to anime-page descriptions; the app's own sync sheet under the description still shows every tracker's real numbers. (2) **AniList episode titles on the main catalogue too**: anime pages now pull each franchise entry's licensed-stream feed from AniList (public data — no login needed) and use its episode titles whenever the feed *provably* belongs to that entry — entry-sized within ±3, or an exact whole-season list sliced by the stacked index, the same proven guard the anime catalogue already used; AniList thumbnails fill gaps where TMDB has no still. Descriptions, air dates and runtimes still come from TMDB because AniList has no per-episode fields for them — that's an AniList limitation, not a choice. (3) **Multi-season anime pages — more robust AND faster**: the whole prequel/sequel franchise walk is now cached for 30 minutes (previously N serial AniList queries on EVERY page load), announced-but-unaired sequels no longer appear as phantom 1-episode "seasons", duplicate (season, episode) rows are dropped defensively, and the log prints `anilistTitles=N` so a filtered logcat shows exactly how many rows got AniList titles. BDIX/link fetching untouched — v83's no-verifier behavior stays. |
| **v83** | 2026-07-30 | **The pre-playback source verifier is gone, at your request.** The v76 liveness probe (the thing that HEAD-checked every link before showing it and hid the ones that didn't answer) is fully removed — links are now listed exactly as the sites give them, zero pre-checks, zero added delay before the list appears. Everything else stays: one install = both catalogues (v82), season-accurate headers + rebuilt settings screen (v81), dead-link report and the parallel discovery + sitemap tier from v74/v75. Note: with no verifier, a link that sits on a dead server can appear in the list again — if a pick stalls, just tap the next link for that episode. |
| **v82** | 2026-07-30 | **The StreamPlay model, finished: ONE extension, ONE module, ONE source of truth.** The separate Wizstream-Anime module is retired from the repo — the anime provider and resolvers now live permanently inside Wizstream (no build-time mirroring, no dual-module drift, nothing else to install or update). In the app a single install still shows TWO sources — `Wizstream` and `Wizstream-Anime`, same names as always, so bookmarks + tracking keep resolving. ⚠️ **If you still have the old separate "Wizstream Anime" extension installed, uninstall it** (Settings → Extensions) or the anime catalogue appears twice. Update plumbing hardened: the GitHub Action now sanity-checks every build (package count, index contents, the anime module's absence from the index) before publishing, fails loudly instead of shipping a partial update, and uploads the built packages as archived artifacts on every run so a release never depends on a single deploy step. Carries everything from v81 (one-install binding, season-accurate headers, rebuilt settings screen) and v76 (dead-link probe/prune). |
| **v81** | 2026-07-30 | **One install, both catalogues.** Wizstream now registers the anime catalogue itself — the separate Wizstream-Anime extension is no longer needed. Season headers are now season-*accurate* (they use art from the season's own episodes, so a Season 1 page can't show Final-Season art). Rebuilt settings screen: rounded section cards, live search, per-group counts and toggles, API-key status pills, All on / All off. MAL & Kitsu progress lines removed from anime descriptions (AniList's own stays) and the ratings line now sits on its own line above the synopsis. |
