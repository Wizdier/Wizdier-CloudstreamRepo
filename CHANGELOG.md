| **v96** | 2026-08-05 | **Two new sources you asked for — shuttletv.su and anikage.cc — both wired with the "no HTTP 2004 / no 3003" guarantee.** (1) **Anikage** (anikage.cc) joins 🎌 Anime-web: a SvelteKit SPA built for TV, fully AniList-id-keyed (no search step, no auth, no PoW — the catalogue is open). Its API exposes five streaming providers (Neko default, Koto, Wave, Dib, Megg), each with sub + dub, and returns plain `embedUrl` fields pointing at hosts the engine already supports from v92+ (vivibebe.site, megaplay.buzz, otakuhg.site, playmogo.com, playeng.animeapps.top, play.echovideo.ru, gn1r5n.org, myvidplay.com, vidtube.site) — every provider is queried in parallel, embed URLs are deduped, and each is handed to `loadExtractor` so the existing extractors do the heavy lifting. Honest caveat: the `url` field returned for Megg is XOR-encoded with a key prefix `"aproxy20"` (full key not derived — Megg is provider #5 and the other four cover everything); Megg-encoded URLs are silently skipped in favour of the embed-URL fallback from the other providers. (2) **ShuttleTV** (shuttletv.su) joins 🌐 Web for movies AND series: it's a Next.js App Router catalogue backed by TMDB, but the actual stream is served by **cinesrc.st** — a self-described "Free video streaming API built by the ShuttleTV team" — a TMDB-id-keyed embed service analogous to vidsrc.to / 2embed.cc. Movie: `cinesrc.st/embed/movie/{tmdbId}`; TV: `cinesrc.st/embed/tv/{tmdbId}?s={season}&e={episode}`. **Honest caveat (do not over-promise):** cinesrc.st protects its m3u8 with a 2-stage proof-of-work — bootstrap → `/api/c/issue` (hashcash-style) + `/api/c/stage2/issue` (WASM-based via `/pow-v3.wasm`) — that is too complex to port to Kotlin server-side. This resolver emits the embed URL via `loadExtractor`, so Cloudstream's WebView loads the page client-side, solves the PoW in JavaScript, and the m3u8 is intercepted from network traffic. That works on modern Android phone WebViews but MAY fail on older Android TV WebViews (the v95 ani.zip/CF challenge class of issue). If ShuttleTV returns no links on your TV, test the embed URL directly in the TV browser — `https://cinesrc.st/embed/movie/550` — if it plays, the failure is Cloudstream's WebView not handling the PoW (need a WebView update); if it shows "Just a moment…", your IP/TV stack is CF-blocked at the edge (not code-fixable our side). Both new sources get on/off switches in Open Settings, labelled and blurbed like the rest. |
| **v95** | 2026-08-03 | **Old-TV fix: the web sources (Cineby, Moonflix, Bingr, CineJoy) silently dying on your ~2018 Android TV, root-caused and repaired.** Your report was exact: anime sources resolve, but the four web sources list nothing. The mechanism, verified end to end: on anime pages the TMDB id those four APIs are gated on comes from **one single call to api.ani.zip** — a Cloudflare zone that (with certain network/old-stack combinations, exactly your TV's WebView-v70 era stack) never answers. Moonflix — whose own server stack is not behind Cloudflare at all — should come back in full on the TV straight away; Cineby, Bingr and CineJoy come back wherever their Cloudflare edge still talks to that box (their requests also got browser-parity hardening this version). Not a rollback of anything — nothing you had was removed; this only adds a fallback where there used to be a single point of failure. Bonus for diagnosis: a null TMDB id now prints a loud logcat line naming exactly which web sources skipped, so one TV logcat settles any future case instead of guesswork. |
| **v94** | 2026-08-03 | **Three new sources you asked for — cinejoy.to, 2dhive.com and anihq.cc — every one wired with the "no HTTP 2004 / no 3003" guarantee: nothing is ever listed that the player would choke on.** (1) **CineJoy** (cinejoy.to) joins 🌐 Web for movies AND series: its streams hide behind a bespoke sealed protocol ("lumen-wire-v2" — HKDF-SHA256 key schedule, AES-256-GCM-sealed requests, and a scrypt proof-of-work the app mints on the fly in about a second, exactly like the site's own player). All five of its providers (Lisbon, Solara, Joy, Arrow, Sakura) are queried in parallel and each keeps its own catalogue, so where one is silent another usually answers — with the site's subtitle tracks attached. The punchline: its video CDN 403s/418s every request **without a cinejoy.to Referer** (verified live: bare hits get a grumpy anime-girl 418 page instead of a playlist), and the master playlists keep audio in separate rendition files — so links carry the exact Referer the CDN demands and are emitted as whole masters ("keep-master", the same treatment that fixed AniZone sound in v93), otherwise you'd have met picture-without-sound or raw HTTP errors. (2) **AniHQ** (anihq.cc) joins 🎌 Anime-web with sub + dub rows: its players are scrambled through a six-step obfuscation (ROT13 → junk-strip → base64 → character-shift → reverse → base64) — re-implemented and byte-verified against the site's own jwplayer setup — ending at a signed HLS master that plays with **zero special headers**. (3) **2Dhive** (2dhive.com) joins 🎌 Anime-web, keyed by your show's MAL id so there is no title-search gamble: MegaPlay streams resolve through its getSources API (Referer must be exactly the megaplay.buzz root — anything else 403s, verified), and the nine-language subtitle tracks come along; the alternate Babastream server is Cloudflare-guarded against datacenters, so that hop resolves on your device instead of our test box — if the guard wins there, the row simply doesn't appear. The guarantee that titles this release: every link from all three sources must pass a **device-side live probe** (a 512-byte range fetch that drops dead links, 4xx/5xx and HTML error pages) **before it can be shown**, and anything that looks like a webpage instead of a video is discarded at the same gate — that's precisely the class of failure behind your HTTP 2004 ("dead response") and 3003 ("unparseable data") errors, so these sources cannot produce them. All three get on/off switches in Open Settings, labelled and blurbed like the rest. |

conservative hardening: bounded transport retries where one dropped
connection used to blank whole screens, graceful degradation instead of
error banners, deduped links, and once-compiled regexes in per-card hot
